# Layout — `src/noble_agent/`

Bảng layer đầy đủ: vai trò từng module trong `src/noble_agent/`. Tách khỏi CLAUDE.md 2026-08-06.

Ngược lại: [`../../CLAUDE.md`](../../CLAUDE.md)

### Layout under `src/noble_agent/`

| Path | Role |
|---|---|
| `__main__.py` | CLI entry. Reads `--transport`, loads `.env`. When `USE_UNIFIED_AGENT=true`: dispatches to `transport/livekit/worker.py:run_worker` if `TRANSPORT_BACKEND=livekit` (registers outbound to livekit-server, no public listener), else `server/http.py:run_server` (binds `ws_port`). |
| `_runner.py` | Compat shim — re-export `__main__.main` cho vài script còn import `noble_agent._runner.main`. Không có logic. |
| `config.py` | `UnifiedSettings` (pydantic-settings, ~370 field). All env vars live here — bảng Key configuration bên dưới chỉ là phần hay dùng, không đầy đủ. |
| `agent/facade.py` | `NobleAgent` — per-conversation instance created via `create(session_id, *, tenant_id)`, pinning its `tenant_id` + config `version` for the whole conversation (BR05) and re-entering `use_tenant()` around every turn. `TurnRunner`s are cached, NOT a singleton: `_runners: OrderedDict[(tenant, version), TurnRunner]` (cap 256, LRU) for the versioned path + `_legacy_runners[tenant]` for version 0 (store-disabled/package). `_build_runner_from_ctx` branches on `AGENT_CONFIG_SOURCE`: `db` → `_agent_def_from_db(tenant_id)` (`read_published_config` → `parse_config` → `build_agent_def_from_config`); else `load_agent_def(config.json)`. Public API: `stream_response`, `reset`, `get_customer`, `set_customer_fields`, `suggest_followups`, `ensure_version_built` (SP-D warm). |
| `agent/orchestrator.py` | `TurnRunner` — per-turn orchestration, semcache, async summary, transcript. |
| `agent/runner.py` | `run_turn` — LLM + tool loop, history invariant enforcement. |
| `agent/base.py` | `AgentDef` (frozen dataclass) + two builders. **Legacy:** `load_agent_def(persona_dir, *, tool_names, agent_name=None, brand=None)` — `tool_names` (the offered-tool list) supplied by the caller from `TenantContext.enabled_tools`; reads `config.json` (name/model/temperature/max_tokens — no `"tools"` key). **DB:** `build_agent_def_from_config(skeleton_dir, config, *, model, temperature, max_tokens)` — composes SOUL/RULES from the shared skeleton via `compose_persona` (marker-strip + render), offers `config.enabled_tools`, renders brand from `config.identity.brand`, gates feng-shui via `config.feng_shui`; model/temp/max_tokens come from `.env` (ops knob), not a per-tenant file. |
| `agent/agent_config.py` | (DB path) Pure, no I/O. `Identity` / `Scope` / **`Style`** / `AgentConfig` frozen dataclasses + `parse_config(raw_jsonb_dict) -> AgentConfig`. `Style` = closed vocab, giá trị lạ rơi về default: `tone` ∈ `lich_su`\|`than_thien`(default)\|`ngan_gon`, `reply_length` ∈ `ngan`\|`trung_binh`(default)\|`chi_tiet`; mỗi giá trị map sang một dòng prompt tiếng Việt qua `_TONE_DESC`/`_REPLY_LEN_DESC` (soft guidance, không phải hard rule). `CORE_TOOLS` (4, always unioned in canonical order) + `OPTIONAL_TOOLS` (8, valid names only, unknown/reserved dropped). `feng_shui` forced False unless `recommend_units` ∈ enabled. Defaults: agent_name `"Trợ lý"`, honorific_self `"em"`, honorific_customer `"anh/chị"`, handoff_department `"CSKH"`, media_channel `"noblex_app"`, data_source `"pg_kb"`. Contract: `docs/handoff/spec.md` §4. |
| `agent/persona_compose.py` | (DB path) `strip_tool_regions(text, enabled_optional, feng_shui)` (pure string — remove `<!-- TOOL:x -->` / nested `<!-- FENG_SHUI -->` blocks for disabled tools, then drop the markers of kept regions) + `compose_persona(skeleton_dir, config) -> (soul, rules)` (strip then jinja-render `{{identity.*}}`/`{{scope.*}}`). |
| `persona/` | (DB path) **Shared persona skeleton, one copy in the wheel — split per delivery channel (2026-08-12): `persona/chat/` + `persona/voice/`**, each holding the full 4-file set `SOUL.md` / `RULES.md` (with tool-region markers + identity/scope placeholders), `PROMPT_TEMPLATE.md` / `CUSTOMER_PROFILE.md` (started as byte-copies; they diverge by design — voice ngắn gọn, chat đầy đủ, so tool-doc edits go in BOTH `RULES.md`). NO `config.json`, no flat top-level files. The channel is declared by the transport at its entry point: `NobleAgent.create(..., channel=)` is REQUIRED ("chat"\|"voice"); `agent/base.py::resolve_persona_dir(base, channel)` picks `base/<channel>` when the subdir exists, else falls back to `base` (flat legacy tenant bundles serve both channels). Runner registries are channel-keyed: `_runners[(tenant, version, channel)]` / `_legacy_runners[(tenant, channel)]`. This replaces the per-tenant `persona/` bundle when `AGENT_CONFIG_SOURCE=db`. Marker/placeholder convention: `docs/handoff/spec.md` §10. |
| `tenant/` | **Per-tenant config bundle loader** (SaaS Phase 3a+3b). `context.py` = `TenantContext` (frozen: `tenant_id`, `data_source`, `persona_dir`, `enabled_tools`, `rankers`, `media_channel`, `brand`). `loader.py` = `get_tenant_context()` singleton — reads `TENANT_ID` (default `noble`) → parses `tenants/<id>/manifest.toml` (stdlib `tomllib`, fail-loud). **This phase only `persona_dir` + `enabled_tools` are consumed (facade); `data_source`/`brand`/`rankers`/`media_channel` are declared as the manifest's source of truth for later slices. Provider source is now resolved from the current tenant's manifest `data_source` (per-tenant, via `get_provider` → `_active_source`); `NOBLE_DATA_SOURCE` is only the fallback for a bundle-less tenant (2026-07-31 tenant-contextvar work).** **De-globalize (2026-07-31, Plan 1 — tenant contextvar spine):** which tenant a request belongs to is resolved PER-REQUEST via `tenant/current.py` `current_tenant()` (a `ContextVar`, `use_tenant(tid)` scopes a block; unset → falls back to `settings.tenant_id` so a single-tenant deploy is byte-identical) — never read `settings.tenant_id` on the request/data path. Every module-level cache that used to be a bare global is now tenant-keyed off `current_tenant()`: `get_tenant_context()` (`_ctx_by_tenant` dict), the `find_project` `ProjectNameIndex` singleton (`_INDEX_BY_TENANT`), the data-provider factory's `_INSTANCES` (keyed `(tenant, source)`), and the facade's runner registries (`_runners: OrderedDict[(tenant, version), TurnRunner]` cap 256, `_legacy_runners` per-tenant dict). `NobleAgent` captures its tenant at `create()` (`self.tenant_id`) and re-enters `use_tenant(self.tenant_id)` around every turn so a shared multi-tenant process never leaks tenant A's runner/index/provider into tenant B's turn. **Formerly process-level, now shared/per-request (2026-08-03):** the LiveKit worker's agent-dispatch registration uses a SHARED `settings.livekit_agent_name` (one worker pool for all tenants; tenant travels in participant metadata / chat `X-Tenant-Id` — shared-worker-routing feature); the SP-D heartbeat runs a `HeartbeatSupervisor` that emits for EVERY active tenant in the store (not just `settings.tenant_id`); and `app_session`'s LiveKit token minting resolves the tenant per-request (body `tenant_id`, fallback `settings.tenant_id`) and carries it in participant metadata. `agent_dispatch_name` is deleted. Isolation gate: `tests/unit/tenant/test_deglobalize_isolation.py`. Full audit + scope: `docs/superpowers/specs/2026-07-31-single-agent-multitenant-decision-memo.md` (PG RLS `_tenant_id()` and noisy-neighbor guards are separate follow-up plans, not this one). **(2026-07-29, SaaS slice #1)** A bundle can now also come from the MinIO tenant store (`store.py`/`materialize.py`/`provisioning.py`/`cli.py`), materialized to a local dir at load time, instead of only the in-wheel package — gated by `TENANT_STORE_ENABLED` (default `false` = in-wheel package only, unchanged). **Org above tenant (2026-08):** `identity.py` mints `org_id = org_<rand8>` and a deterministic `tenant_id = <org_id>_<slug(name)>` (no random suffix; uniqueness within an org enforced by rejecting duplicate display names, across orgs by the `org_` prefix); `org_of(tenant_id)` recovers the org by prefix-parse (no lookup); `current.py::current_org()` derives the org from the ambient tenant (tolerant → `None` for legacy ids like `noble`). MinIO store nests keys `<org>/<tenant>/` with 2-level `list_ids`; `noble-tenant` CLI gained `create-org`/`create-tenant`/`list-orgs`/`migrate-org-layout`. Isolation gate: `tests/unit/tenant/test_org_isolation`. **Config-from-DB is the planned successor to this MinIO-bundle flow** (see the Architecture "one shared agent" section + `docs/handoff/spec.md` §8): when `AGENT_CONFIG_SOURCE=db`, the config lives in Postgres and the persona is the shared `persona/` skeleton — retiring the MinIO tenant store / org-nesting / SP-C versioning-on-MinIO **for the config flow** is an explicit follow-up, not done yet. **Follow-up DONE (2026-08-04):** in db-mode `get_tenant_context()` no longer touches MinIO at all — it returns `tenant/db_context.py`'s cached `TenantContext` built straight from the published config (`context_from_config`); `_build_store` (MinIO) is now reachable only on the `legacy` path and is marked deprecated in its own docstring. See the Architecture "one shared agent" section for the other 3 retired surfaces (gateway creds, worker version, heartbeat). |
| `tenants/noble/` | Noble's tenant bundle for the **`legacy` config path** (inside the package so it ships in the wheel like the former `agent/definitions/`). `manifest.toml` (tenant_id, data_source, persona_dir, `[tools].enabled` = the offered tools + `rankers`/`media_channel`, `[brand]` company/app_name). `persona/` = **prompt source of truth** on this path: `SOUL.md`, `RULES.md` (operational protocol + tool catalog + style + guardrails), `PROMPT_TEMPLATE.md`, `CUSTOMER_PROFILE.md`, `config.json` (name/model/temperature/max_tokens — no tool list). Editing the prompt is a markdown edit, no code change. (git-mv'd from `agent/definitions/`, now deleted.) The old per-tenant custom tool `tools/service_customer.py` (CSBH media over Qdrant `media_v3`) was **removed** — noble ships no custom tool. `tenants/demo_acme/` is an inert example tenant. (On the `db` path this bundle is bypassed for the shared `persona/` skeleton — see Architecture.) |
| `agent/prompts/builder.py` | `build_system_prompt(agent, customer, summary)` — jinja2 compose. No longer injects a project table or code enum (removed 2026-07-22 — see `find_project` below); Luna resolves a spoken project name to a code on demand via the `find_project` tool. |
| `agent/tools/` | **12 tools offered to Luna** (pre-sale set; `config.json` gates the offer), incl. `find_project` (resolve a spoken project name → canonical code via `data/project_matching/ProjectNameIndex`; on `resolved` sticks the code into `customer.project_interest` so downstream data tools default an empty `project_code` to it), `discover_projects` (funnel discovery — the former `list_projects` reshaped: returns one page — top-K by hot-first stable ranking + `total` match count + `suggested_narrow` axes — instead of dumping the full roster; `index` param paginates to the next page with the same filters) and `check_inventory` (còn/hết + đếm theo loại/hướng, summary shape — not a unit list, distinct from `booking.check_availability`). `recommend_units` takes an optional `project_code` to scope the unit recommendation to one project (empty = cross-project). The 3 post-sale tools `verify_identity` / `crm_lookup` / `support_ticket` (and the mock CRM `data/crm_data.py`) were **deleted 2026-08-18** — no tenant could ever offer them; post-sale goes to `escalate`. **Dispatch goes through a `ToolSpec` registry (SaaS Phase 3c):** `registry.py` (`ToolSpec` frozen: name/schema/executor/`dirties_customer`/`read_only`/`tenant`; `resolve(tenant,name)` = tenant entry then `"*"` built-in), `builtins.py` (the 12 standard tools registered as `tenant="*"` built-ins via thin adapters over the tool modules — the source of the `dirties_customer`/`read_only` flags that the dispatcher + semcache read), `dispatcher.py` (`_exec` = `registry.resolve(...).executor(args, **bag)`; outer `dispatch()` invariants unchanged; a per-tenant custom tool shadows a built-in of the same name). Schemas in `schemas.py`. `booking` gồm 4 action (`check_availability` / `schedule` / `list` / `modify`), chỉ cần dự án + ngày + giờ (không tên/SĐT). |
| `data/project_matching/` | On-demand project-name resolver backing `find_project` (no per-session code enum, no prompt table). `fold.py` (VN phonetic fold + metaphone normalization), `channels.py` (trigram / token-set / phonetic similarity scores), `index.py` (`ProjectNameIndex` — weighted fusion of the 3 channels + optional embedding channel, region/brand additive boosts, confidence gate → `resolved` / `ambiguous` / `not_found`; thresholds `_FLOOR=0.55` / `_MARGIN=0.09` / `_AMBIG_FLOOR=0.45` / `_AMBIG_DELTA=0.10`, calibrated against `tests/.../test_resolution_eval.py`). Built once at bootstrap by `orchestrator._build_project_index()` from `db_project_registry.registry_rows()` and installed into the `find_project` tool module singleton (`find_project.set_index`). |
| `agent/memory/` | Per-caller **cumulative snapshot** memory, **always on** whenever a real phone is present (no enable flag). `snapshot.py`: `merge_snapshot(old_snapshot, history)` — LLM merge (old snapshot + full call history → new free-text narrative; careful merge prompt keeps distinct old facts, updates conflicting ones to latest, `""` on failure so the old snapshot is preserved), `build_short_term_context(settings, phone, current_session_id)` — renders the snapshot narrative + last-K turns of the most recent prior session (within `USER_MEMORY_SINCE_DAYS`) into one prompt block. `__init__.py` entry helpers: `update_snapshot_after_call(settings, *, phone, session_id, history)` — fire-and-forget at call end (acquire Redis lock → load old → merge → save → release; log-and-continue on any error), `short_term_block(settings, *, phone, session_id)` — waits for any in-flight merge (bounded) then builds the bootstrap block. Persisted via `storage/pg_data_plane.py::persist_contact` / `read_contact_snapshot` (Postgres `tenant_data.contacts.snapshot`, one row per `(tenant, phone)`); the prior-session turns come from `read_session_messages` (`tenant_data.conversation_messages`). Lock `storage/snapshot_lock.py` (Redis `snapshot:lock:{phone}`, TTL `SNAPSHOT_LOCK_TTL_SEC=60`; the next call from the same phone waits up to `SNAPSHOT_LOCK_WAIT_SEC=10` for the merge to clear, else proceeds with the old snapshot). Folded into the frozen `customer_block` at first-turn bootstrap (`orchestrator.py`), not a separate prompt var — no recall tool. Spec: `docs/superpowers/specs/2026-07-13-user-snapshot-memory-redesign-design.md`. |
| `agent/llm/{client,anthropic_provider}.py` | `StreamingClient` — ordered provider fallback (anthropic → openai → gemini); `stream_completion` returns `(content, tool_calls)`. |
| `agent/rag/` | FlatStore (e5-large + BM25 hybrid), `noble_kb.query_noble_kb` (single entrypoint for the `kb_search` tool — renamed from `noble_search` in Phase 3d; the internal `query_noble_kb`/`_NobleKBAdapter` names are unchanged). |
| `agent/summary/` | `summarize_and_persist` — async, fires when `len(history) - summary.covers_turns > summary_threshold_K (=8)`; keeps `summary_keep_tail (=4)` raw turns. |
| `agent/catalog.py` | `normalize()` — 15 canonical Noble codes (NCLB / NCTH / NCRS / NPLB / NPTH / NTTL / SSLC / SSC / SGR / SGI / SRP / SCHN / SBR / ASM / ALUMI). Longest-first alias, ambiguous → `""`. Codes are no longer all 4-char (ALUMI=5). |
| `agent/qwen_transcript.py` | Optional per-session transcript writer. |
| `semcache/` | Optional semantic response cache (predictor → sandbox → store). Off by default (`NOBLE_SEMCACHE_ENABLED=false`); only `mode=full` hits replay live, `partial` falls back to live run. |
| `voice/` | `vad/silero.py`, `turn_detection/smart_turn.py`, `audio/`, `voice_agent.py` (LLM → sentence buffer → TTS → audio out), `sentence_buffer.py`, `audio_guard.py`, `gender_detector.py`. Pluggable `stt/` and `tts/`. |
| `server/` | `ws_handler.py`, `http.py` (health + `/api/config` + LiveKit token + `/api/v1/app/session` + `/api/call-me` + static; the CSKH `/api/v1/sales/*` surface and `rate_limit.py`/`csv_export.py` were deleted 2026-08-18 — Portal owns it), `session.py`/`base_session.py`, `text_chat.py`, `admission.py`, `app_session.py` (provisioning phiên cho NobleX app — chat). |
| `telephony/` | `ari_client.py`, `audiosocket.py`, `session.py`, `resampler.py`. |
| `transport/livekit/` | `worker.py`, `room_session.py`, `agent_audio_io.py`, `codec_utils.py`. |
| `storage/` | `redis_client.py`, `repo.py` (3-key `StateRepo` + WATCH summary update), `connection.py` (**Redis only** — Mongo removed 2026-08-18), `models.py` (Meta / Customer / ThreadMessage / ThreadSummary / State), `postgres_client.py` (asyncpg pool + `tenant_conn`), `pg_data_plane.py` (PG write/read DAOs). `agent_config_store.py` (DB config path) — `read_published_config(tenant_id) -> PublishedConfig|None`: reads the Portal VIEW `agent_published_config` via `tenant_conn` (RLS auto-scoped), parses the `config` jsonb, writes a last-good copy to `/var/lib/noble/agent_config_cache/<tenant>.json`, and serves last-good on a DB error (E01). |
| `metrics/` | `collector.py` — in-session latency collection (`MetricsCollector` / `Timer`). The Mongo `session_metrics` sink + aggregate reporter were deleted 2026-08-18; historical roll-up has no home yet. The `services/` package (CRM / SMS / outreach / profile clients) was deleted — zero importers. |
| `observability/phoenix_tracing.py` | `init_tracing(settings)` — boot-time self-hosted Arize Phoenix OTEL LLM tracing. Auto-instruments the Anthropic + OpenAI SDKs (the OpenAI instrumentor covers all four openai-compat slots: openai / dashscope / vllm / gemini). Endpoint-gated no-op, `batch=True` background export, idempotent per process, log+continue on failure. Called from both transports at boot. |
| `SMOKE.md` | Manual smoke checklist. Run after any change touching turn loop, prompt, or transport. |
