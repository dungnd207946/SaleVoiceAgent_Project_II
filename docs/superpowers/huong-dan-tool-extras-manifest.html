Hướng dẫn mở rộng: Tool · Extras · ToolParam · Manifest

Bấm tab để chuyển chủ đề. Mỗi tab là một quy trình độc lập, có mã minh hoạ.

Thêm một tool CHUẨN (built-in, mọi tenant dùng chung)

Dùng khi năng lực mới là tiêu chuẩn — mọi tenant đều có thể bật. Tool sống ở core, được đăng ký là built-in tenant="*". Cần sửa core (chấp nhận), nhưng KHÔNG đụng dispatcher (registry lo việc gọi).
  1. Viết executor agent/tools/<ten>.py

    Một hàm async trả về chuỗi (thứ Luna đọc). Lấy dữ liệu từ provider/DB tuỳ ý.

    async def run(args: dict) -> str:
    provider = providers.get_provider(get_settings())
    data = await provider.get_inventory_summary(args.get("project_code",""))
    if data is None:
        return ESCALATE_SIGNAL          # không có dữ liệu → chuyển chuyên viên
    return json.dumps(ser.inventory_json(data), ensure_ascii=False)
  2. Khai schema JSON agent/tools/schemas.py — thêm 1 entry vào dict SCHEMAS

    Đây là cái LLM nhìn thấy: tên tool, mô tả (KHI NÀO gọi + LÀM GÌ + 1 ví dụ), tham số.

    SCHEMAS["check_inventory"] = {
  "type": "function",
  "function": {
    "name": "check_inventory",
    "description": "Tóm tắt tồn kho MỘT dự án… Ví dụ 'dự án còn nhiều căn không'.",
    "parameters": {"type":"object",
      "properties": {"project_code": {"type":"string", "description":"Mã dự án canonical."}},
      "required": ["project_code"]},
  },
}
  3. Đăng ký vào registry qua adapter agent/tools/builtins.py

    Adapter mỏng nhận "túi kwargs" (dùng cái nào cần + **_), gọi executor. Rồi thêm dòng vào _BUILTINS.

    async def _check_inventory(args, *, dispatcher, **_):
    dispatcher.default_project_code(args)     # điền mã mặc định nếu để trống
    return await check_inventory.run(args)

# (name, executor, dirties_customer, read_only)
_BUILTINS = [
    ...
    ("check_inventory", _check_inventory, False, False),
]

    dirties_customer = True nếu tool sửa hồ sơ khách (kích hoạt build lại prompt). read_only = True nếu tool chỉ đọc (semcache dùng để phân loại).

  4. Bật tool cho tenant tenants/<id>/manifest.toml — thêm tên vào [tools].enabled

    Đăng ký ≠ được offer. Tên phải nằm trong enabled thì agent của tenant đó mới thấy.

  5. Dạy Luna khi nào gọi tenants/<id>/persona/RULES.md — thêm dòng vào bảng "Tool catalog"

    Không có bước này, LLM biết tool tồn tại nhưng không rõ tình huống nào nên gọi.

Nhớ: tên tool trong 4 chỗ (schema key + function.name + builtins + manifest) phải trùng khít. Test: make test-unit.

Thêm CUSTOM TOOL riêng cho MỘT tenant

Điểm mạnh: thả một file, KHÔNG sửa core, KHÔNG sửa dispatcher/schemas/builtins. Tool chỉ tenant đó thấy; có thể ghi đè built-in cùng tên (chỉ cho tenant đó).
  1. Tạo file tool trong bundle tenant tenants/<id>/tools/<ten>.py

    Decorate bằng @tool. Executor nhận túi kwargs — lấy provider, tenant + **_. Đây là mẫu thật demo_acme/tools/loan.py:

    from noble_agent.agent.tools.registry import tool

_SCHEMA = {
  "type": "function",
  "function": {
    "name": "check_loan",
    "description": "Kiểm tra điều kiện vay (custom tool của Acme).",
    "parameters": {"type":"object",
      "properties": {"amount": {"type":"number"}}, "required": []},
  },
}

@tool(name="check_loan", schema=_SCHEMA, tenant="demo_acme", read_only=True)
async def check_loan(args, *, provider, tenant, **_):
    # provider = nguồn dữ liệu của chính tenant này; gọi API riêng tuỳ ý
    return f"loan:{tenant}:{args.get('amount', 0)}"
  2. Để trống file __init__.py tenants/<id>/tools/__init__.py

    KHÔNG viết from . import loan. Loader tự pkgutil-walk mọi file trong tools/ lúc boot, nên chỉ cần thả file là decorator tự chạy → tự đăng ký.

  3. Bật trong manifest tenants/<id>/manifest.toml 
    [tools]
enabled = [ "find_project", "kb_search", ..., "check_loan" ]   # ← thêm tên
  4. (Tuỳ chọn) Ghi vào RULES.md của tenant để Luna biết khi nào gọi.

Chữ ký executor — túi kwargs có sẵn

kwargLà gì
argsTham số LLM điền (positional đầu tiên)
providerNguồn dữ liệu đang hoạt động (gọi API riêng của tenant)
tenantId tenant hiện tại
state / customer / session_idNgữ cảnh phiên (nếu cần)
callbacks / rag / dispatcherÍt dùng; lấy qua **_
Isolation: resolve("acme","check_loan") ra tool này; resolve("noble","check_loan") ra None. Tenant khác không thấy.

Thêm EXTRAS (Tier-1) — field phụ cho Luna THẤY

Khi nguồn có field mà form chuẩn không mô hình hoá, và bạn chỉ muốn hiển thị nó (không lọc). Ví dụ thật: nbx.fundType → "Loại quỹ căn".
Quan trọng — khai ở ĐÂU: hiện tại extras khai trên class provider (thuộc tính extra_specs), KHÔNG phải trong manifest.toml. Vì vậy nó gắn theo nguồn dữ liệu (provider), không theo tenant. (Việc đưa vào manifest là slice tương lai — đang deferred.)
  1. Khai metadata trên provider data/providers/<provider>.py 
    extra_specs = (
    base.ExtraFieldSpec(
        key="fund_type",          # key trong túi extras
        label="Loại quỹ căn",     # nhãn VN Luna đọc
        entity="unit",            # unit | project | pricing
        type="string",
        unit="",                  # "vnd" | "m2" | "pct" | "" → tự thêm hậu tố nhãn
        description="Nhóm quỹ căn (vd 'hot').",
    ),
)
  2. Nhét giá trị vào extras khi build DTO 
    extras = {}
if (fund := (raw.get("fundType") or "").strip()):
    extras["fund_type"] = fund
return base.Unit(..., extras=extras)
  3. Xong. Serializer tự render {"Loại quỹ căn": "hot"} vào JSON tool trả về, và system prompt tự sinh phụ lục "Trường dữ liệu bổ sung". Không sửa tool, không sửa manifest.
Nhớ: extras chỉ để đọc/hiển thị. Muốn khách lọc theo field này → sang Tab 4 (ToolParam).

Thêm TOOL PARAM (Tier-2) — ô lọc mới cho tool chuẩn

Khi bạn muốn LLM truyền được một tham số lọc mới mà tool chuẩn không có sẵn. Framework tự thêm ô vào schema + tự lọc kết quả. Không viết code lọc.
Khai ở ĐÂU: giống extras — khai trên class provider (thuộc tính tool_params), chưa phải manifest. Gắn theo nguồn dữ liệu.
  1. Khai param trên provider data/providers/<provider>.py 
    tool_params = (
    base.ToolParamSpec(
        tool="search_units",      # tool đích được thêm ô
        name="fund_type",         # tên param LLM điền
        type="string",
        description="Lọc căn theo nhóm quỹ căn. Chỉ truyền khi khách nêu rõ.",
        maps_to="fund_type",      # key trong extras để so khớp
        match="eq",               # eq|substring|gte|lte|exists|contains
    ),
)
  2. Đảm bảo field có trong extras (như Tab 3) — maps_to trỏ vào đúng key đó.
  3. Xong. Ba việc tự động, không cần code:
    TầngFramework tự làm
    Schemabuild_schemas bơm ô fund_type vào tool search_units
    DispatchGom giá trị param vào UnitQuery.custom_params
    LọcSo unit.extras["fund_type"] với giá trị theo match (safety net)

6 toán tử match

matchÝ nghĩa
eqBằng đúng
substringChứa chuỗi con (không phân biệt hoa/thường)
gte / lte≥ / ≤ (số)
existsCó/không có field (value truthy = phải có)
containsGiá trị nằm trong list
Tối ưu (tuỳ chọn): adapter đọc query.custom_params trong search_units để lọc thẳng ở DB. Framework vẫn re-apply filter sau đó (idempotent) nên không sai.

Viết manifest.toml cho từng trường hợp

Manifest = nguồn chân lý runtime của một tenant: bật tool nào, dùng nguồn nào, brand gì, ranker nào. Nằm ở tenants/<id>/manifest.toml.

Bộ khung đầy đủ (chú thích từng dòng)

tenant_id   = "acme"          # id tenant (trùng tên thư mục)
data_source = "nbx"           # PHẢI mirror NOBLE_DATA_SOURCE đang chạy (test guard)
persona_dir = "persona"       # thư mục persona con (SOUL/RULES/…)

[tools]
enabled = [                   # DANH SÁCH TOOL ĐƯỢC OFFER cho agent này
    "find_project", "kb_search", "discover_projects",
    "get_project_overview", "search_units", "recommend_units",
    "booking", "escalate", "send_media", "check_inventory",
    "check_loan",             # ← custom tool riêng tenant (Tab 2)
]
rankers = ["feng_shui"]       # [] = bỏ → recommend_units tự gỡ param phong thuỷ + bỏ overlay
media_channel = "acme_app"    # kênh gửi media (mới template tên app)

[brand]
company  = "Acme"             # thay {{ brand.company }} trong tool desc + persona
app_name = "AcmeApp"          # thay {{ brand.app_name }}
