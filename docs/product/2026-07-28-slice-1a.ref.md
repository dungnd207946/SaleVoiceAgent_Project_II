# Lát 1a — Postgres schema + isolation + 4 cổng test · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dựng nền Postgres của control plane — schema `control` + `tenant_data`, cơ chế isolation đa-tenant, hợp đồng đọc `agent_api` cho agent, và 4 cổng test chứng minh isolation không vỡ.

**Architecture:** Base table nằm ở `tenant_data`, agent **không có quyền nào** trên đó. Agent đọc qua **view definer** ở schema `agent_api`; view lọc tenant bằng `portal.current_tenant()` — hàm suy tenant từ **`session_user`** (`agent_<tenant>`), nên session không thể tự khai tenant khác. RLS trên `tenant_data` bảo vệ hai đường ghi của agent (`appointments`, `contacts`) và mọi truy cập của `portal_api`. Publish/rollback dùng chung một hàm plpgsql để `field_policy_live` không bao giờ lệch `live_version`.

**Tech Stack:** Python (bản mới nhất mà `asyncpg` + `testcontainers` resolve được) · uv · asyncpg (runtime) · Alembic + psycopg (migration) · Postgres 18-alpine · pytest + testcontainers

## Global Constraints

- **Postgres sàn cứng ≥ 15**, dùng bản mới nhất. Ghi vào `docker-compose.dev.yml` và README.
- **Giá tiền lưu `bigint` VND**, không phải tỷ. Không có cột nào tên `*_ty`.
- **Agent role không được có privilege nào trên schema `tenant_data`** ngoài `appointments` + `contacts`. Có test canh.
- **`portal_api` và `agent_*` không được là superuser, không `BYPASSRLS`, không `CREATEROLE`, không là owner của bảng nào.** Có test canh (`test_role_privileges.py`).
- **`portal_migrator` là DDL-only**, không dùng lúc runtime. *Không test được trong testcontainers* — ở đó `POSTGRES_USER` là bootstrap superuser. Yêu cầu production (việc của runbook deploy, không phải test): tạo `portal_migrator` là **non-superuser** chỉ có `CREATEDB`/`CREATEROLE` + owner của ba schema.
- **Không dùng ORM.** Truy vấn runtime bằng asyncpg + SQL thuần. Alembic chỉ chạy `op.execute()` với SQL thuần, không có model.
- **Tất cả file SQL/Python comment + docstring bằng tiếng Việt** (khớp `reference/santa-agent-cms`).
- Ruff line-length **120**, target theo `pyproject`, rules `E,F,W,I,UP,B,SIM`. TypeScript chưa dùng ở lát này.
- **6 toán tử `match_op` duy nhất:** `eq · substring · gte · lte · exists · contains`. Là CHECK constraint, không phải quy ước.

## Ba chỗ sửa so với spec

Soạn plan làm lộ ba lỗi trong `docs/superpowers/specs/2026-07-28-tenant-portal-control-plane-design.md`. Plan này theo bản đúng; spec sẽ được cập nhật cùng lúc.

### C1 — `security_invoker = true` là SAI (nghiêm trọng)

Spec §5.4 ghi `WITH (security_invoker = true)` là bắt buộc. Nhưng `security_invoker` khiến Postgres kiểm **quyền của người gọi trên base table** — nghĩa là agent role phải được `GRANT SELECT ON tenant_data.units`. Khi đã có quyền đó, agent **query thẳng base table** và **bỏ qua toàn bộ gate cột** (`commission`, `bank_support`, `csbh_full`). Cơ chế "VIEW lo cột" bị vô hiệu.

Bản đúng: **view definer** (mặc định, `security_invoker = false`) ở schema riêng `agent_api`. Agent có `USAGE` trên `agent_api` + `SELECT` trên view, **zero privilege** trên `tenant_data`. Vì definer view chạy bằng quyền owner nên RLS của owner không áp — view **phải tự lọc tenant** trong `WHERE`.

Và tenant phải suy từ **`session_user`**, không phải `current_user`: trong definer view `current_user` trả về **owner của view**, không phải agent. `session_user` là role đăng nhập, chỉ đổi được bằng `SET SESSION AUTHORIZATION` (cần superuser).

Đổi lại: mất defense-in-depth của RLS trên đường đọc. Bù bằng hai thứ — agent không có quyền chạm base table (mạnh hơn RLS), và `portal.current_tenant()` fail-closed (trả `NULL` → `tenant_id = NULL` → 0 hàng).

### C2 — `tenants.status` vừa lưu vừa suy ra

Spec §5.1 cho `status ∈ {provisioning, ready, suspended, closed}` nhưng §6.5 nói `ready` **suy ra từ heartbeat**. Không thể vừa lưu vừa suy.

Bản đúng: cột lưu là **`lifecycle ∈ {active, suspended, closed}`** — ý chí của người vận hành. Trạng thái hiển thị (`provisioning · disconnected · publishing · ready`) là **hàm thuần** của `lifecycle` + heartbeat + `live_version`.

### C3 — Bỏ role `portal_importer` khỏi 1a

Spec §6.4 nói importer chạy bằng service role có `BYPASSRLS`. Nhưng quyết định #8 đã đẩy importer API ra ngoài #1; nhập liệu ở #1 là **file import trong ngữ cảnh một tenant**, chạy được bằng `portal_api`. Role `BYPASSRLS` là role nguy hiểm nhất hệ thống — không tạo khi chưa cần.

"""Cấu hình portal. Mọi biến môi trường khai ở đây, không đọc os.environ rải rác."""

from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    database_url: str = "postgresql://portal_migrator:dev@localhost:5433/portal"

    @property
    def alembic_url(self) -> str:
        """Alembic chạy qua SQLAlchemy + psycopg (sync); runtime dùng asyncpg."""
        return self.database_url.replace("postgresql://", "postgresql+psycopg://", 1)


def get_settings() -> Settings:
    return Settings()
```

"""Factory pool asyncpg. Không giữ singleton — caller quản vòng đời."""

import asyncpg


async def create_pool(dsn: str, *, min_size: int = 2, max_size: int = 10) -> asyncpg.Pool:
    pool = await asyncpg.create_pool(dsn, min_size=min_size, max_size=max_size)
    if pool is None:  # asyncpg trả None nếu không dựng được
        raise RuntimeError(f"không dựng được pool tới {dsn}")
    return pool
```

```python
"""schema portal/control + hàm current_tenant + 10 bảng control

Revision ID: 0001_control
Revises: None
"""

from alembic import op

revision = "0001_control"
down_revision = None
branch_labels = None
depends_on = None


def upgrade() -> None:
    op.execute("CREATE SCHEMA portal")
    op.execute("CREATE SCHEMA control")

    # Tenant hiệu lực của session.
    #   - Role đăng nhập dạng agent_<tenant>  -> suy từ session_user, KHÔNG override được.
    #   - Role khác (portal_api)              -> lấy từ GUC app.tenant_id.
    # Dùng session_user (KHÔNG dùng current_user): trong view definer, current_user là
    # owner của view, không phải role đang gọi.
    # Trả NULL khi không xác định được -> mọi so sánh tenant_id = NULL ra false (fail-closed).
    op.execute(
        """
        CREATE FUNCTION portal.current_tenant() RETURNS text
        LANGUAGE sql STABLE AS $$
            SELECT coalesce(
                substring(session_user::text from '^agent_(.+)$'),
                nullif(current_setting('app.tenant_id', true), '')
            )
        $$
        """
    )

    op.execute(
        """
        CREATE TABLE control.tenants (
            id            text PRIMARY KEY,
            name          text NOT NULL,
            lifecycle     text NOT NULL DEFAULT 'active'
                          CONSTRAINT tenants_lifecycle_check
                          CHECK (lifecycle IN ('active', 'suspended', 'closed')),
            plan          text NOT NULL DEFAULT 'trial',
            live_version  integer,
            created_at    timestamptz NOT NULL DEFAULT now()
        )
        """
    )

    op.execute(
        """

"""role portal_api + RLS trên tenant_data

Revision ID: 0003_roles_rls
Revises: 0002_tenant_data
"""

from alembic import op

revision = "0003_roles_rls"
down_revision = "0002_tenant_data"
branch_labels = None
depends_on = None

_TABLES = (
    "projects",
    "units",
    "loan_products",
    "rate_schedules",
    "insurance_plans",
    "appointments",
    "contacts",
)


def upgrade() -> None:
    # portal_api: role runtime của Portal API. NOLOGIN cho tới khi deploy đặt mật khẩu.
    # KHÔNG có BYPASSRLS — kể cả bug quên WHERE cũng không rò chéo tenant.
    op.execute("CREATE ROLE portal_api NOLOGIN")
    op.execute("ALTER ROLE portal_api WITH LOGIN")
    op.execute("GRANT USAGE ON SCHEMA portal, control, tenant_data TO portal_api")
    op.execute("GRANT EXECUTE ON FUNCTION portal.current_tenant() TO portal_api")
    op.execute("GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA control, tenant_data TO portal_api")
    op.execute("GRANT USAGE ON ALL SEQUENCES IN SCHEMA control, tenant_data TO portal_api")

    # RLS: tenant hiệu lực lấy từ portal.current_tenant().
    #   USING      -> chặn ĐỌC hàng của tenant khác
    #   WITH CHECK -> chặn GHI hàng sang tenant khác
    # current_tenant() = NULL  ->  tenant_id = NULL  ->  false  ->  0 hàng (fail-closed).
    for table in _TABLES:
        op.execute(f"ALTER TABLE tenant_data.{table} ENABLE ROW LEVEL SECURITY")
        op.execute(
            f"""
            CREATE POLICY tenant_isolation ON tenant_data.{table}
                USING (tenant_id = portal.current_tenant())
                WITH CHECK (tenant_id = portal.current_tenant())
            """
        )


def downgrade() -> None:
    for table in _TABLES:
        op.execute(f"DROP POLICY tenant_isolation ON tenant_data.{table}")
        op.execute(f"ALTER TABLE tenant_data.{table} DISABLE ROW LEVEL SECURITY")
    op.execute("REVOKE ALL ON ALL TABLES IN SCHEMA control, tenant_data FROM portal_api")
    op.execute("DROP ROLE portal_api")
```

"""Helper mở connection đã gắn tenant.

Mọi truy vấn tenant_data của Portal API PHẢI đi qua tenant_conn(). Đặt
app.tenant_id bằng set_config(..., is_local => true) nên nó tự hết hiệu lực khi
transaction kết thúc — connection trả về pool không mang tenant của request trước.
"""

from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

import asyncpg


@asynccontextmanager
async def tenant_conn(pool: asyncpg.Pool, tenant_id: str) -> AsyncIterator[asyncpg.Connection]:
    if not tenant_id:
        raise ValueError("tenant_id rỗng — tenant_conn() luôn cần tenant tường minh")
    async with pool.acquire() as conn:
        async with conn.transaction():
            await conn.execute("SELECT set_config('app.tenant_id', $1, true)", tenant_id)
            yield conn

```python
"""Suy trạng thái hiển thị của tenant.

Cột LƯU trong control.tenants chỉ là lifecycle (active/suspended/closed) — ý chí
của người vận hành. Trạng thái người dùng thấy được SUY RA từ lifecycle +
heartbeat + live_version, nên nó tự lành: pod chết -> disconnected, pod lên lại
-> ready, không có trạng thái nào phải sửa tay.
"""

from datetime import datetime, timedelta

# 4.5 lần chu kỳ poll 20s của agent — chịu được vài lần miss mà không báo động giả.
HEARTBEAT_STALE_AFTER = timedelta(seconds=90)

_VALID_LIFECYCLE = frozenset({"active", "suspended", "closed"})


def derive_tenant_status(
    *,
    lifecycle: str,
    live_version: int | None,
    running_version: int | None,
    last_seen_at: datetime | None,
    now: datetime,
) -> str:
    """Trả một trong: closed · suspended · provisioning · disconnected · publishing · ready."""
    if lifecycle not in _VALID_LIFECYCLE:
        raise ValueError(f"lifecycle không hợp lệ: {lifecycle!r}")

    # Ý chí người vận hành thắng mọi tín hiệu runtime.
    if lifecycle == "closed":
        return "closed"
    if lifecycle == "suspended":
        return "suspended"

    # Chưa từng có pod báo về, hoặc chưa publish lần nào.
    if last_seen_at is None or live_version is None:
        return "provisioning"

    # Pod chết thì nói pod chết — không báo "đang xuất bản" cho một pod không tồn tại.
    if now - last_seen_at > HEARTBEAT_STALE_AFTER:
        return "disconnected"

    if running_version != live_version:
        return "publishing"

    return "ready"
```
