# Pluggable backends — STT / TTS / Speaker / LLM

Chi tiết từng backend cắm-được: chọn qua env, lazy-import, fallback chain, gotcha vận hành.

Ngược lại: [`../../CLAUDE.md`](../../CLAUDE.md)

### Pluggable backends

Select via env vars; lazy-imported.

- **STT** (`STT_BACKEND`): `soniox` | `sherpa` | `elevenlabs` | `qwen3asr` | `remote`. `remote` — client WebSocket tới service `noble-stt-service` thường trú (`voice/stt/remote.py` → `voice/service/stt_server.py`); load model một lần ngoài worker. Add a backend: implement `STTBase` in `voice/stt/<name>.py`, register the lazy import in `server/session.py`. **Init-time fallback chain** `remote → soniox → sherpa` (`STT_FALLBACK_CHAIN` in `voice/fallback.py`): `_init_stt` (in `server/base_session.py`) tries `resolve_order(STT_BACKEND, chain)` — the configured backend stays the head, the rest of the chain follows — and the first backend whose `start()` succeeds serves the whole session. Init/start failures only (a backend that comes up healthy then dies mid-call does NOT trigger fallback). Chain exhausted → `self.stt=None` and the existing `{"type":"error"}` client callback fires **exactly once**. `qwen3asr` and STT-`elevenlabs` are not in the chain, so they yield a single attempt → no auto-fallback (behavior unchanged). `sherpa` is model-agnostic and currently serves the **hynt-bilingual** streaming Zipformer: the encoder/decoder/joiner ONNX **filename stem is auto-discovered** by globbing `SHERPA_MODEL_DIR` for the family selected by `SHERPA_MODEL_QUANTIZE` (`false` → `encoder-*.onnx` excluding `*.int8.onnx`; `true` → `encoder-*.int8.onnx`); `tokens.txt` is fixed. (`SHERPA_MODEL_NAME` was removed — the stem is no longer hard-coded.) `_discover_model_stem` raises a clear `ValueError` if >1 triplet matches a family (clean the dir to exactly one), returns `None` (→ download) if zero. Requires the optional dep `pip install -e ".[stt-sherpa]"` (`sherpa-onnx>=1.10`) — without it `_get_recognizer` raises `ImportError`, `_init_stt` swallows it and sets `stt=None`, and the call is silent (mic in, no transcript, no TTS). hynt-bilingual emits **ALL-CAPS** + punctuation; `SHERPA_PRESERVE_CASE=false` (its configured default) lowercases + sentence-caps, `true` keeps the raw caps. **Auto-provision:** when `SHERPA_MODEL_DIR` lacks the files for the requested family, `_ensure_model_present` pulls them from `SHERPA_HF_REPO` (default `NobleX-AI/zipformer-streaming-bilingual`; live `.env` uses `NobleX-AI/santa-stt`) at `revision=SHERPA_HF_REVISION` (default `prod`) via `huggingface_hub.snapshot_download` using `HF_TOKEN`, then re-globs (still missing → `FileNotFoundError`) — so CD images (models/ is gitignored) self-provision on first launch. `snapshot_download` runs on every boot (etag-cached → unchanged files not re-fetched, latest `prod` picked up). Mount a volume for `models/` to avoid re-downloading. **Startup pre-warm:** `voice/prewarm.py::prewarm_voice_models()` eagerly calls `_get_recognizer()` once at boot (gated on `STT_BACKEND==sherpa`; when `STT_BACKEND=remote` the gate is false, so prewarm is intentionally skipped as the remote STT service owns the recognizer singleton) from BOTH transports (aiortc `server/http.py::_run_server_async`, livekit `worker.py::_prewarm`); a failure logs and boot continues (lazy-load + fallback chain remain the runtime net). **STT input gate** (`STT_INPUT_GATE_MODE`, default `off`): `voice/stt_input_gate.py::SttInputGate` optionally blocks PCM frames from reaching the STT engine. Modes: `off` = passthrough (original behaviour); `rms` = per-frame RMS energy threshold (replaces the removed `AUDIO_GUARD_FRAMES_GATE_ENABLED`); `vad` = Silero VAD drives the gate (VAD already drives interrupts; this adds STT-input blocking). All modes include a K-chunk pre-roll lookback (`AUDIO_GATE_PREROLL_CHUNKS`, default `3`) so speech onset is never clipped. In `base_session.process_audio_frame`, the VAD loop runs first, then `SttInputGate.gate()` decides whether to pass the chunk to the STT backend. `rms` tuning: `AUDIO_GATE_MIN_RMS` / `AUDIO_GATE_REQUIRED_CONSECUTIVE` / `AUDIO_GATE_BARGE_IN_RMS`. `vad` tuning: `STT_VAD_GATE_HANGOVER_MS` (keep gate open N ms after VAD speech ends). When a gate mode is `rms`/`vad`, closed frames are backfilled with synthetic zero-PCM silence (`STT_GATE_KEEPALIVE_MAX_SEC`, default `2.0`s cap) fed to the STT engine so the recognizer's trailing-silence endpoint still fires — finalization timing is unchanged, real noise stays blocked, and it is backend-agnostic (zeros are plain PCM, no protocol change). The injected silence bypasses `_utterance_pcm`.
- **TTS** (`TTS_BACKEND`): `vieneu` (local) | `elevenlabs` (WebSocket streaming) | `remote`. `remote` — client WebSocket tới service `noble-tts-service` thường trú (`voice/tts/remote.py` → `voice/service/tts_server.py`); load model GPU một lần ngoài worker. Add a backend: implement `async stream(text) -> AsyncIterator[bytes]` in `voice/tts/<name>.py`, add it to the builder map in `VoiceAgent._create_tts` (`voice/voice_agent.py`). **Init-time fallback chain** `remote → elevenlabs → vieneu` (`TTS_FALLBACK_CHAIN` in `voice/fallback.py`): `_create_tts` tries `resolve_order(TTS_BACKEND, chain)` and returns the first builder that constructs without raising (vieneu eagerly loads its model at construct, so a load failure is caught here). An unknown backend (not in the chain) maps to the vieneu builder — preserving the legacy "anything not elevenlabs → vieneu" contract. All builders raise → the **last** exception is re-raised (TTS is required; no silent None). Note: `_init_tts_warmup` still gates on `TTS_BACKEND == "elevenlabs"`, so an elevenlabs-after-remote-fallback session does not pre-warm (accepted — WS connects lazily on first `stream()`). `vieneu` auto-routes on `VIENEU_BACKBONE_REPO` (`voice/tts/vieneu.py:_load_tts`): a local dir with `*.gguf` or a HF repo whose name contains `gguf` → the legacy GGUF loaders; any other HF repo → `_load_tts_santa`, which serves the fine-tuned **`NobleX-AI/santa-tts`** (safetensors `Qwen3ForCausalLM`). Santa path: `gguf_filename=None` is **mandatory** to force the transformers branch for a safetensors repo; backbone loads on `VIENEU_BACKBONE_DEVICE` (default `cuda`), the decode-only ONNX int8 codec (`VIENEU_CODEC_REPO`) on `VIENEU_CODEC_DEVICE` (default `cpu`). The vieneu library has **no `revision` kwarg**, so `_resolve_backbone_repo` fetches the backbone at `revision=VIENEU_HF_REVISION` (default `prod`) via `snapshot_download` (every boot, etag-cached) and hands `Vieneu(...)` the **local snapshot dir** as `backbone_repo`; a local dir / gguf path passes through unchanged, and a download failure logs + returns the original repo id so the library's own download still runs. The **codec repo stays on its default revision (NOT pinned)**. The voice is **not** cloned at runtime — it's read from a precomputed `reference/presets.json` (`{default_voice, presets:{name:{codes,text}}}`; `VIENEU_PRESETS_PATH` overrides, default `voice/tts/reference/presets.json`), selected by `VIENEU_VOICE_ID` (default voice **luna**). Build that file offline with `python scripts/build_vieneu_voices.py --default luna`: it encodes `reference/*.wav` → codes via the **full torch** `neuphonic/neucodec` (the runtime int8 codec is decode-only, so it cannot encode) — needs the `tts-vieneu` extra (incl. `librosa`). **Risk:** vieneu hardcodes `use_chat_format=True` only for the repo `pnnbao-ump/VieNeu-TTS`, so santa-tts defaults to the non-chat prompt template; if the fine-tune was trained chat-format the audio comes out garbled — set `VIENEU_USE_CHAT_FORMAT=true` to override. Verify by listening to a generated sample. **Startup pre-warm:** `prewarm_voice_models()` eagerly calls `_load_tts()` once at boot (gated on `TTS_BACKEND==vieneu`; when `TTS_BACKEND=remote` the gate is false, so prewarm is intentionally skipped as the remote TTS service owns the model and the client WS connects lazily on first `stream()`) from both transports; a failure logs and boot continues. Note: `_init_tts_warmup` gates on `TTS_BACKEND == "elevenlabs"` for the legacy warmup; when `TTS_BACKEND=remote` it likewise does not run. Heavy imports stay function-local so `make test-unit` collects without the optional dep.
- **Speaker policy** (`SPEAKER_MODE`, default `off`): `off` | `single` | `multi`. `SPEAKER_VERIFICATION_ENABLED=true` is deprecated — resolved to `single` by `config.resolve_speaker_mode()` with a deprecation warning. **2026-09-03: SpeakerRegistry + SpeakerTracker** (`voice/speaker_tracker.py`) replace the old fixed-cadence chunk engine. `SpeakerRegistry` holds N identities (each a `CentroidSet`) that live for the WHOLE session — no more per-turn reset: FIFO cap (`SPV_MAX_IDENTITIES`, single mode pins it to 1) evicts the oldest identity that is NOT the current asker when a safe candidate exists, falling back to evicting the asker itself only when there is none; the registry also tracks an `asker` pointer that the drop rule in `_on_final` manages. Read threshold is `SPEAKER_MATCH_THRESHOLD`; the write (centroid-add) threshold is stricter, `+ SPV_ADAPT_MARGIN`, so a borderline read never becomes the new baseline. `SpeakerTracker` runs **in parallel with STT**, probing an ACCUMULATING window (from utterance start) at each mark in `SPV_PROBE_MARKS_SEC` (default `0.25,0.4,0.6,0.9,1.3`s); each mark has its own threshold, `SPEAKER_MATCH_THRESHOLD + SPV_PROBE_BONUS[i]` (shorter windows need a higher bar), so the first verdict can land at ~0.25s (fail-open via `SpeakerRegistry.match_asker` when there is no asker yet). Once the mark chain is exhausted without a match, probing switches to a SLIDING tail window (`SPV_PROBE_TAIL_WINDOW_SEC`/`SPV_PROBE_TAIL_HOP_SEC`) instead of accumulating further — accumulating past that point would blend a voice change into one hybrid embedding. A `speaker` verdict while the agent is talking fires the interrupt **immediately at that probe** (via the addressee gate's soft-pause when enabled, else `_handle_interrupt` directly); `non-speaker`/`unknown` just leaves the agent talking. `finalize()` (called from `_on_final`) is the ONLY place that writes centroids: it re-embeds the utterance in overlapping windows (`SPV_ENROLL_WINDOW_SEC`/`SPV_ENROLL_HOP_SEC`), takes the largest mutually-consistent cluster (pairwise cosine ≥ `SPV_ENROLL_CONSENSUS_SIM`), and enrolls it only when that cluster has ≥ `SPV_ENROLL_MIN_CLUSTER` windows — an inconsistent or too-short utterance enrolls nothing (fail-open; the floor is left as-is) instead of writing a noisy centroid. The 5-branch drop rule in `_on_final` keeps a final unless it is mid-turn AND belongs to a DIFFERENT identity than the current asker; a mismatch-streak valve (`SPV_MISMATCH_STREAK_MAX`) only counts finals with positive evidence of a stranger (`cluster_size >= SPV_ENROLL_MIN_CLUSTER` but no identity match) — evidence-less short finals (e.g. "dạ") never bump or reset it — and once the streak trips, `drop_asker()` clears the asker so the floor reopens instead of staying locked to a wrong identity. Identity uses `SpeakerEmbedder` (unchanged) — **backend-agnostic: works identically with sherpa AND soniox**, embedding offloaded via `asyncio.to_thread`. Embedder is remote-default: `SPEAKER_REMOTE_URL` set → posts PCM to `noble-speaker-service` HTTP `/embed`; else local sherpa CAM++ ONNX (auto-provisioned from `SPEAKER_HF_REPO` at `SPEAKER_HF_REVISION` into `SPEAKER_MODEL_DIR`). `voice/service/speaker_server.py` + `noble-speaker-service` console script unchanged (binds `SPEAKER_SERVICE_HOST:SPEAKER_SERVICE_PORT`, default `0.0.0.0:9100`). `prewarm_voice_models()` loads local model at boot when `SPEAKER_MODE != off` AND `SPEAKER_REMOTE_URL` empty. Zero overhead when `SPEAKER_MODE=off` (`_speaker_tracker is None`). **Scope:** `base_session` only (browser aiortc + livekit). Telephony is **not** covered.
- **LLM**: at least one provider key required. Five slots `facade.build_llm_providers` may construct (each built only when its key/model is set): `anthropic` (`ANTHROPIC_*`), `vllm` (`VLLM_*`, built when `VLLM_MODEL` set), `openai` (`OPENAI_*`, hosted OpenAI — default base_url `api.openai.com` → real-OpenAI request shaping), `dashscope` (`DASHSCOPE_*`, Alibaba DashScope/Qwen OpenAI-compat cloud, built when `DASHSCOPE_API_KEY` set), `gemini` (`GEMINI_*`). **The three OpenAI-compatible endpoints (local vLLM / OpenAI / Qwen) are now DISTINCT slots — do not overload `OPENAI_*` for all three.** Default build order: vLLM OFF → `anthropic → openai → dashscope → gemini`; vLLM ON → `vllm → openai → dashscope → gemini → anthropic` (anthropic LAST as a safety tail). Build order is only the fallback tie-break. Every LLM path (main agent, summary, semcache) uses the **same** per-provider model map (`config.provider_model_map`: each provider asked with its own `<P>_MODEL`). What differs per path is the **primary provider pin**: `NOBLE_AGENT_MODEL` / `NOBLE_SUMMARY_MODEL` / `NOBLE_SEMCACHE_MODEL`. Each value must equal one of the configured `<P>_MODEL` values; `config.primary_for` looks up which provider owns that name and `StreamingClient` reorders the chain so that provider runs first. Fallback to the other providers (each with their own `<P>_MODEL`) still kicks in if the primary fails. Empty pin / unknown name → default chain order (warning logged). (`OPENROUTER_*` / `GROQ_*` / `CEREBRAS_*` config fields exist but are NOT wired into the chain.)
- **Thinking mode**: two flags, both in `agent/llm/thinking.py` helpers (`disable_thinking_kwargs`, `ThinkStripper`, `strip_think`).
  - `NOBLE_LLM_ENABLE_THINKING` (default `false`) — whether the model *generates* thinking. On `StreamingClient` (shared by main agent / summary / semcache). When off: merge the provider disable kwarg (openai/vLLM → `extra_body.chat_template_kwargs.enable_thinking`; dashscope → `extra_body.enable_thinking` (top-level, DashScope's own switch); gemini → `reasoning_effort="none"`; anthropic → none) **and** strip leaked `<think>...</think>` from both the stream and the returned content — so thinking is absent everywhere incl. history. When on: client is passthrough (returns raw → `state.history` keeps thinking, persisted cross-turn and forwarded to the LLM).
  - `NOBLE_LLM_SHOW_THINKING` (default `false`) — display-channel only. The facade `_Callbacks` strips `<think>` from `on_token` (the UI/TTS channel) unless `show_thinking`. `server/text_chat.py` passes `settings.llm_show_thinking`; the voice path never passes it, so **TTS always strips**. History (client return) is untouched. `eval/predict.py` always `strip_think`s its prediction.
  - Net: thinking lives in `state.history` only when generation is on; it reaches the chat UI only when `SHOW_THINKING=true`; it never reaches TTS or eval.
- **RAG retrieval**: `NOBLE_RAG_BACKEND={flat_store, qdrant, hipporag, grep_faq, kb_service, empty}` (default `flat_store`). `kb_service` (**rewritten 2026-08-05, no longer an HTTP client**) now runs the retrieval **in-process**: embed the query dense (per `EMBED_BACKEND`) + BM25-sparse (in-process fastembed), then ONE Qdrant hybrid query over `<tenant>_documents` — the `query_rag:8016` hop it used to make is retired, and as of 2026-08-06 so is any embed-service dependency on this path. See the "KB Qdrant backend" section. `qdrant` is a **separate, unrelated hybrid** on Qdrant: dense (e5-large 1024d) + BM25 **sparse** both on an app-owned clone collection, fused server-side (RRF), on a DIFFERENT deployment (`QDRANT_URL`, not `QDRANT_URL`). The clone is rebuilt from another team's read-only root collection at server-agent startup (or via `noble-rag-sync`); on Qdrant error the adapter falls back to a disk BM25 index. See the "Qdrant hybrid backend" section.
- **Transport**: `TRANSPORT_BACKEND={aiortc, livekit}`.
